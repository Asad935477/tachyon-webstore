# Tachyon Webstore

Headless e-commerce monorepo. Turborepo + pnpm. `apps/web` (Next.js storefront, port 3001),
`apps/server` (Hono + tRPC API, port 3000), `packages/{ui,api,auth,db,env,config}`.

Start: `pnpm run dev`. Lint/format: `pnpm run check` (Biome, tabs, double quotes).

## ⚠️ Next.js 16

`apps/web` runs Next 16, which has breaking changes vs. most training data. **Read
`node_modules/next/dist/docs/` before writing Next-specific code.** In this monorepo the
`next` package resolves from `apps/web`, not the repo root. See `apps/web/AGENTS.md` — that
block is auto-generated by `next dev`; commit it with your work rather than deleting it.

# UI redesign — "Void & Light"

**Full spec:** https://claude.ai/code/artifact/9dd6a10d-d2cf-412f-865c-751d9bdf1e0a

Read that artifact before starting any phase — it holds the palette, type scale, shader
source, micro-interaction inventory, photography brief and per-phase acceptance criteria.
In Claude Code, fetch it with the Artifact tool: `action: "read"` with that URL.

## Direction, in one paragraph

A dark room with a light source in it. Depth comes from luminance, not drop shadows;
elevation is a rim-light, not a blur. Products are the brightest things on screen. One
ambient WebGL field carries the atmosphere across every page. Minimal, restrained — motion
is a closed list, not a vibe.

## Settled decisions — do NOT reopen these

These were explored and rejected. A fresh session re-proposing them wastes the user's time.

| Question | Decision |
|---|---|
| Ground | **Dark-committed.** No light theme. Not a token swap — out of scope. |
| Display typeface | **None.** Geist for everything. Syne was proposed and reversed. |
| Loading screen appearance | **Unchanged.** Two redesigns were built, both worse. Repair the code, never restyle it. |
| Splash → site handoff choreography | **Dropped.** Splash stays self-contained and fades. |
| 3D / camera work | **No.** Every effect is a fragment shader on a flat quad. 2.5D via luminance parallax only. |
| Shader budget | Ambient field + targeted moments. Three canvases max, one shared GL context for cards. |

**The rule behind most of these:** a shader may be *substrate* (grain, light falloff,
diffusion you don't consciously notice) but never *decoration*. If you can point at an effect
and name it, it doesn't belong.

# Known issues (from the audit — not yet fixed)

Out of scope for the UI phases, but don't be confused by them:

- **Catalogue silently falls back to mock data.** `packages/api/src/routers/catalog.ts` wraps every Prisma call in `try { } catch { }` and falls through to `packages/api/src/mock/catalog.ts` (825 lines) on any error *or empty result*. Collections and testimonials are mock-only. Checkout only ever queries the real DB — so **if you're browsing mock data, every checkout throws "Product does not exist."**
- **Prices are `Float`, not `Int`.** Values are cents (34900) but the column type is `Float`, contradicting the code comments and the synopsis. `packages/db/prisma/schema/catalog.prisma`.
- **No Admin CMS.** `apps/web/src/app/dashboard/` is Better-T-Stack boilerplate. The synopsis describes a full CMS module that doesn't exist.
- **`role` is never checked.** No admin gate anywhere in `packages/api`, `packages/auth` or `apps/server`. One `protectedProcedure` total, and it's boilerplate.
- **No tests, no CI.**
- **Storefront is client-rendered.** 13 of 16 pages are `"use client"`; no `generateMetadata`, `generateStaticParams`, `sitemap.ts` or `robots.ts`. Convert *after* the UI phases — 6–8 rewrite the same files.

# Working style

- The user wants to see visual work rendered, not described. Build a demo or publish an artifact rather than explaining a look in prose.
- Verify claims against the running app or the source before asserting them.
- Don't over-design. When something already works, repair it rather than replacing it.
